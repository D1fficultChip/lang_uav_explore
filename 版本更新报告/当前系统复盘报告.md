# 当前系统复盘报告

## 1. 当前阶段总判断

目前系统已经不再是“自然语言 + 检测器 + 简单规则切换”的原型，而是已经形成了一套较完整的分层智能架构：

- 上层有 `Qwen` 驱动的任务编译器
- 中间有带世界状态、验证、恢复、reasoner 和 skill 管理的 central runtime
- 感知侧有 `GSAM2 fast proposal + semantic verification`
- 搜索侧有增强后的 `FALCON semantic exploration skill`
- 执行侧有 `EGO_navigate`
- 位置链路上已经有 `TargetLocalizationSkill`
- 基于位置的高层 skill 已经补到：
  - `ObserveSkill`
  - `TrackDynamicTargetSkill`

整体上，系统已经从“功能堆叠阶段”进入“主架构成形、应转向联调和评测”的阶段。

## 3. 当前系统具备的功能

从功能上概括，目前系统已能完成以下能力链：

### 3.1 搜索链

- 自然语言任务解析
- 目标与 cue 的 proposal 生成
- 中枢根据语义需求调度 `FALCON`
- 在探索时使用显式语义控制信号

### 3.2 验证链

- proposal 进入 verifier
- semantic verifier 做高层语义判断
- verify window 抑制过早推进
- 若证据不足，可继续观察、重试或恢复

### 3.3 定位链

- GSAM2 输出 `mask`
- localizer 结合 depth / odom 算出 `target_position_world`
- 中枢 runtime 回读定位结果

### 3.4 观察链

- 发现目标后可进入 `ObserveSkill`
- 调用 EGO 接近
- 执行悬停观察
- 失败则回退到观察起始点

### 3.5 跟踪链

- 持续位置解算
- `TrackDynamicTargetSkill` 条件更新目标点
- 调用 EGO 跟踪
- 丢失后做短时恢复与回退

## 4. 系统当前是怎么运行的

系统当前的主运行链路可以概括为：

1. 自然语言任务进入 `Qwen task compiler`
2. 编译出结构化 plan
3. `central runtime` 执行 stage
4. 写 `perception_request.json`
5. GSAM2 生成 proposal 与 mask
6. semantic verifier / runtime verifier 判定证据
7. 若仍处于搜索阶段，则调度 `FALCON semantic exploration skill`
8. 若定位成功，则可进入：
   - `OBSERVE`
   - `TRACK`
9. `ObserveSkill / TrackDynamicTargetSkill` 通过 EGO 执行
10. runtime 根据 success / failure / diagnostics / recovery 决定推进、回退或恢复

从运行时分层上看，系统已经形成：

- `Task Compiler`
- `Verified Runtime`
- `Fast Proposal`
- `Semantic Verification`
- `Semantic Search Skill`
- `Localization Skill`
- `Observe / Track Skill`
- `EGO/FALCON/PX4`

## 5. 现在能不能做系统性测试

### 5.1 代码级和模块级测试

可以。

当前已经具备：

- 多数 Python 模块的语法自检基础
- runtime event log
- benchmark evaluator

这意味着：

- 可以做模块级 dry-run
- 可以做日志级指标计算
- 可以做 runtime 行为联调

### 5.2 系统级联调测试

可以开始做，但需要完成启动链路整合。

当前最适合先跑的两条闭环是：

- `SEARCH -> LOCALIZE -> OBSERVE`
- `SEARCH -> LOCALIZE -> TRACK`

如果这些链路跑通，说明系统已经形成真正的 end-to-end 技术闭环。

### 5.3 真机系统测试

可以准备，但目前还没有完成实机接入验证。

真机前仍需确认：

- 真实 topic 名
- depth 和 RGB 是否对齐
- 相机到机体的外参
- odom 世界系定义
- catkin 编译与 launch 串接

也就是说：

- 框架与接口已基本具备
- 实机接入条件已清楚
- 但尚未完成实机闭环验证

## 6. 还缺哪些必要东西

### 6.1 系统工程层面的必要缺口

这些不是新功能，而是联调前必须补齐的工程项：

- launch 文件和启动链整理
- 各模块的 topic / frame / extrinsic 参数模板
- 最小系统测试 checklist
- evaluator 与最终 event schema 的一致性验证
- 一套更稳定的运行脚本

### 6.2 方法与能力层面的必要缺口

从方法完整度来看，仍值得继续补强的主要是：

- localization 的多帧融合与稳健性增强
- track 的滤波、预测与更稳回退
- relation/context 任务下的更强验证
- benchmark 任务族与自动评测真正跑起来

需要强调的是：

- 现在已经不再明显缺“新的主类型 skill”
- 更缺的是现有 skill 的稳定联调和实验验证

## 7. 系统有鲁棒性吗

### 7.1 已具备的鲁棒机制

从架构层面看，系统已经具备以下鲁棒性来源：

- FALCON / EGO / PX4 是传统算法 backbone
- runtime 有 verifier，不会仅靠一次 proposal 就推进
- semantic verifier 可提供二次判断
- 有 verify window，可抑制 premature progression
- 有 diagnostics / recovery / fallback
- `ObserveSkill` 有 rollback
- `TrackDynamicTargetSkill` 有 target lost fallback

也就是说：

- 系统已经具备“闭环纠错”机制
- 不再是一条不可回头的 rollout 链

### 7.2 当前鲁棒性的限制

但目前的鲁棒性主要仍是“架构级鲁棒”，而不是“充分实证后的鲁棒”。

当前主要限制包括：

- localization 还是第一版，没有多帧融合
- track 没有速度预测和滤波
- observe / track 还未经过系统级长时联调
- 遮挡、深度异常、定位跳变等场景下的表现还未量化

因此更准确的说法是：

**架构上已经有鲁棒机制，代码上也有回退和恢复，但鲁棒性仍需通过系统测试和 benchmark 实验证明。**

## 8. 目前的工作靠谱吗

### 8.1 从架构角度看，靠谱

现在的系统分层已经比较清楚：

- compiler
- runtime
- proposal
- semantic verify
- search skill
- localization skill
- observe / track skill
- low-level execution

而且最近几轮开发都在尽量维持边界：

- 不让大模型直接发控制
- 不让中枢层过度侵入底层算法
- C++ skill 尽量通过 `yaml + topic` 接上层

这说明架构方向是稳的。

### 8.2 从代码落地看，靠谱

这批工作里，很多关键模块已经不是“设计稿”，而是实代码：

- semantic verifier
- FALCON semantic exploration
- target localization
- observe
- dynamic track

这说明系统已经从概念阶段走到可联调阶段。

### 8.3 从完成度看，还差最后一段

当前还不能说系统已经“充分验证完成”，因为还差：

- 系统级联调
- benchmark 任务级测试
- 实机接口接入
- 若干关键参数和稳定性增强

所以最准确的评价是：

**目前工作整体是靠谱的，主干已经成形，代码也已经具备相当的实现深度；但系统仍处于“应从继续堆功能转向验证、联调和评测”的阶段。**

## 9. 下一阶段的重点建议

当前阶段最不建议做的，是继续无节制添加新模块。

更建议的工作顺序是：

1. 跑通最小闭环：
   - `SEARCH -> LOCALIZE -> OBSERVE`
2. 再跑：
   - `SEARCH -> LOCALIZE -> TRACK`
3. 整理 launch / config / topic / frame 参数
4. 让 benchmark evaluator 真正吃到新的 runtime log
5. 设计并运行任务族测试

也就是说：

**下一阶段重点应从“开发新功能”转向“系统联调、阶段复盘和 benchmark 化验证”。**

## 10. 结论

当前系统已经完成了从“概念型语言任务执行系统”到“具备真实闭环骨架的 UAV 智能架构”的关键跨越。

现在已经可以比较明确地说：

- 系统有编译层
- 有中枢层
- 有语义探索 skill
- 有语义验证
- 有位置解算
- 有观察 skill
- 有动态跟踪 skill
- 有 runtime 验证、恢复与事件记录

所以系统的主要问题已经不再是“有没有功能”，而是：

- 能不能稳定联起来
- 能不能通过任务族验证
- 能不能形成 benchmark 级证据

这也是下一阶段最值得投入的方向。
