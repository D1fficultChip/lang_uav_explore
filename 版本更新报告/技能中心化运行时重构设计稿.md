# 技能中心化运行时重构设计稿

## 1. 重构目标

基于当前进展，项目下一阶段建议从：

- `proposal / verification / reasoning` 逐步堆到中枢层

调整为：

- **中枢层负责高层智能与技能编排**
- **能力性模块尽量下放为 skill**

也就是说，后续系统主线应收敛成：

**LLM-enhanced skill-centric verified runtime**

---

## 2. 核心判断

### 2.1 中枢层的智能性不应主要体现为

- 自己做几何求解
- 自己做动态目标跟踪
- 自己做具体 waypoint 规划
- 自己替代 EGO / FALCON / tracking / localization

### 2.2 中枢层的智能性应主要体现为

- 当前阶段需要什么信息
- 该调用哪个 skill
- skill 的调用顺序与切换逻辑
- 证据是否足够
- 当前失败属于哪一类
- 下一步是继续、补验证、切换 skill、回退还是终止

一句话概括：

**中枢层的大模型应该是高层 skill executive，而不是底层算法替代器。**

---

## 3. 建议架构

建议将系统正式划分为四层：

1. `Task Compilation Layer`
- 自然语言任务 -> `plan.json`

2. `Verified Runtime Layer`
- `executor + world_state + verifier + diagnostics + recovery + guard`

3. `Skill Layer`
- 将能力模块统一封装成 skill

4. `Execution Layer`
- EGO / FALCON / PX4 / ROS

---

## 4. 中枢层职责重新定义

## 4.1 中枢层负责

- 任务级理解
- 阶段级推进
- skill 选择
- skill 切换
- skill 验证
- skill 恢复
- bounded replanning

## 4.2 中枢层不负责

- 深度几何解算
- 动态跟踪控制闭环
- 高精度目标定位
- 地图可达性规划
- 精确 waypoint 生成

---

## 5. 推荐 skill 体系

## 5.1 当前可直接包装的 skill

### `FastProposalSkill`
- 后端：GSAM2 / GroundingDINO + SAM2
- 输出：proposal、top-k candidates、proposal uncertainty

### `SemanticVerifySkill`
- 后端：Qwen-class MLLM
- 输出：semantic evidence、failure hypothesis、recommended followup

### `SearchSkill`
- 后端：FALCON

### `NavigateSkill`
- 后端：EGO

### `HoldObserveSkill`
- 后端：hold + runtime

## 5.2 后续可扩展的底层 skill

### `LocalizeTargetSkill`
- 后端：depth + odom + mask + geometry
- 输出：target body/world pose

### `TrackDynamicTargetSkill`
- 后端：改造后的 EGO 或其他 tracking planner
- 输出：动态目标跟踪执行状态

### `InspectTargetSkill`
- 组合 skill
- 内部可串联 proposal -> verify -> localize -> observe

## 6. Skill Contract 设计

建议新增一层统一的 skill contract。

建议新增文件：

- `central_runtime_v0/central_runtime/skills/contracts.py`
- `central_runtime_v0/central_runtime/skills/registry.py`
- `central_runtime_v0/central_runtime/skills/results.py`

每个 skill 至少定义：

- `skill_id`
- `intent`
- `inputs`
- `outputs`
- `preconditions`
- `success_signals`
- `failure_signals`
- `recoverability`
- `safe_stop`
- `runtime_hooks`

这样中枢层调用的就不再是“散乱模块”，而是“有契约的 skill”。

---

## 7. LLM 中枢的输出空间

建议后续逐步把 reasoner 的输出收窄成 skill-level 决策。

推荐输出形式：

- `continue_current_skill`
- `invoke_skill(skill_id, target_entity, mode)`
- `retry_skill(skill_id)`
- `switch_skill(skill_id)`
- `fallback_skill(skill_id)`
- `terminate`

例如：

- `invoke_skill: SemanticVerifySkill`
- `switch_skill: TrackDynamicTargetSkill`
- `fallback_skill: SearchSkill`

这样比直接输出大量动作细节更稳定，也更符合中枢层定位。

---

## 8. 中枢层智能性的五种表现

## 8.1 Epistemic Intelligence

知道当前缺什么信息。

例如：

- proposal 不稳定
- semantic evidence 不够
- target 位置未锁定

## 8.2 Strategic Intelligence

知道下一步该调用哪个 skill。

例如：

- SEARCH -> VERIFY
- VERIFY -> LOCALIZE
- LOCALIZE -> TRACK

## 8.3 Diagnostic Intelligence

知道失败原因属于哪一类。

例如：

- ambiguity
- semantic not supported
- nav stalled
- target lost

## 8.4 Coordination Intelligence

负责 skill 间的衔接。

例如：

- `FastProposalSkill -> SemanticVerifySkill`
- `SemanticVerifySkill -> NavigateSkill`
- `TrackDynamicTargetSkill -> FallbackSearchSkill`

## 8.5 Safety Intelligence

知道什么时候不该推进。

例如：

- 证据不足不允许切阶段
- tracking 丢失必须回退
- localization 不稳不允许进入追踪

## 9. 推荐任务流程示例

假设任务：

“搜索并确认可疑人员，若确认后持续跟踪。”

推荐流程：

1. 中枢调用 `SearchSkill`
2. `FastProposalSkill` 给出候选
3. 若 proposal ambiguity 高，中枢调用 `SemanticVerifySkill`
4. 若语义确认成立，后续可调用 `LocalizeTargetSkill`
5. 若目标位置稳定，调用 `TrackDynamicTargetSkill`
6. 若 tracking 丢失，则中枢选择：
- retry track
- hold observe
- fallback search

这里中枢的智能不在于自己做 tracking，而在于：

- 什么时候进入 tracking
- tracking 失败后怎么办

---

## 10. 与当前已有进展的衔接

当前系统已经有以下基础，可直接支撑 skill-centric 重构：

- `WorldState`
- `Verifier`
- `Reasoner`
- `Semantic Verification Framework`
- `GSAM2 richer proposal`
- `Recovery`

因此下一步并不是推翻已有工作，而是把现有能力重新组织成 skill-centric 架构。

---

## 11. 下一步建议

建议按以下顺序推进：

1. 先定义 `Skill Contract`
2. 将已有能力包装为 skill：
- `FastProposalSkill`
- `SemanticVerifySkill`
- `SearchSkill`
- `NavigateSkill`
- `HoldObserveSkill`
3. 让 reasoner 逐步转成 skill-level decision
4. 给未来底层扩展预留：
- `LocalizeTargetSkill`
- `TrackDynamicTargetSkill`

---

## 12. 最终定位

最终建议将整套方法收敛为：

**以规则化 verified runtime 为安全骨架、以大模型为高层 skill executive、以底层技能模块为能力承载的真实 UAV language agent 系统。**
