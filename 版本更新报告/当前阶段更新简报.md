## 1. 当前目标

当前升级工作的总体目标是：

- 保留现有真实 UAV 可飞的规则安全骨架
- 不改成端到端 VLA
- 把系统逐步升级成：
  - `GSAM2 = fast proposal`
  - `MLLM = semantic verification`

## 3. 当前系统形态

到目前为止，项目已经从：

- `plan -> detect -> transition`

升级成：

- `plan -> proposal -> verifier -> semantic verification framework -> runtime reasoning -> bounded action -> skills`

从架构上看，当前系统已具备以下分层雏形：

1. `Task Compiler`
2. `Fast Proposal Layer`
3. `Semantic Verification Layer (framework ready)`
4. `Verified Runtime + Bounded Reasoner`
5. `Skill Execution Layer`

---

## 4. 当前还没做满的部分

虽然框架已经搭起来了，但以下部分目前仍属于“预留/初版”状态：

1. semantic verification 还没有正式接入你选定的具体大模型 API。
2. `insert_verify_stage` 还没有真正实现成动态插入验证阶段。
3. semantic verification 的输出还没有完全转成更强的 bounded runtime action policy。
4. 几何语义仍未引入，目前只有 2D image-plane spatial hint。
5. relation-aware verification 还没有真正做强。

---

## 5. 当前明确遵守的能力边界

在当前实现中，已经明确避免给模块分配超出其能力范围的任务：

- GSAM2 只承担 fast proposal，不承担复杂任务推理
- semantic verifier 只做语义核验，不直接控制 UAV
- runtime reasoner 只做高层 bounded reasoning，不直接输出低层控制
- FALCON / EGO / PX4 继续承担底层执行与物理一致性

---

## 6. 下一步建议

当前最合适的下一步有两条：

1. 继续补强 semantic verification 与 reasoner 的联动
- 让 semantic evidence 更直接地影响 bounded high-level action

2. 单独设计几何语义接口
- 结合位姿反馈、视角几何或相机反推距离信息

当前系统已经具备了从“自然语言调模块”向“LLM-enhanced verified UAV runtime agent”演进的清晰骨架。
